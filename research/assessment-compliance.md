# MSE907 Assessment 2 and Assessment 3 Compliance Map

The uploaded MSE907 briefs define Assessment 2 as a Work in Progress report and Assessment 3 as the final research report and presentation. Code is evidence for the software artifact, but the assessment also requires written analysis, ethics/culture discussion and communication.

## Assessment 2

### Task 1 / LO1 — Literature Review & Gap Analysis
Required evidence:
- progress beyond Assessment One;
- deeper critical analysis of limitations/inconsistencies;
- explanation of how the findings contribute to the selected gap.

Project evidence:
- `research/requirements-traceability.md`
- SLR/proposal material from the student's earlier assessment
- implementation/design artifacts that operationalize the gap

### Task 2 / LO2 — Project Proposal & Research Design
Required evidence:
- refined RQs;
- project significance/impact;
- detailed methodology justification and data-collection methods.

Project evidence:
- proposal RQs/objectives;
- DSR/mixed-methods methodology;
- technical experiments;
- interoperability and performance evaluation design.

### Task 3 / LO3 — Software Engineering Principles
Required evidence:
- analysis of software-engineering principles such as OOP and agile development;
- explanation of how principles contribute to implementation.

Project evidence:
- service/repository/layered architecture;
- class-based domain services;
- automated tests;
- requirements traceability;
- iterative MVP development/runbook.

### Task 4 / LO4 — Ethical and Cultural Issues
Required evidence:
- data privacy, consent and bias;
- cultural implications and adaptations.

Project evidence:
- `research/ethics/ethical-cultural-analysis.md`
- participant research templates with ethics-approval boundary.

## Assessment 3

### Final Research Report
The final report should integrate:
Literature → Gap → RQs → Objectives → Methodology → Requirements → Design → Implementation → Testing → Evaluation → Discussion → Ethics/Culture → Conclusion.

### Presentation
The final presentation should communicate the project to academic and professional audiences using architecture, workflow, demo and empirical results and should address ethical/cultural issues.

## Evidence-to-rubric rule

The project should not claim an assessment criterion is satisfied simply because code exists. Each claim must be supported by the appropriate report section, artifact, test, empirical result or presentation evidence.
